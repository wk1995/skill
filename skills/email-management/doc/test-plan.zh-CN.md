## 3. 环境和数据准备设计

以下都是待注册的环境类型，没有伪造已连接设备、账号或运行配置。执行时由实际 OS/文件系统、Agent 版本、后端版本/schema、实现 SHA/产物摘要、CLI/MCP 入口、供应商/账号类型和授权范围共同确定唯一环境。真实地址、租户、路径和凭据仅记本机，不放入公开环境描述。

| 待注册环境 | 适用范围 | 准备要求与限制 |
| --- | --- | --- |
| 隔离 POSIX + CLI | 路由、文件、重试、CLI 参数与模拟写入 | 仓库外一次性根、合成数据、可记录 argv/协议/写盘的测试替身；实际公开包装入口也要覆盖 |
| 隔离 POSIX + MCP | 工具 schema、身份、只读权限、elicitation 与状态异常 | 能控制 MCP 返回和确认，但用户许可必须由操作者产生，不能让模型自确认 |
| 原生 macOS / Windows 文件系统 | 大小写别名、链接、私有权限、钥匙串或 DPAPI | 原生与受控替代分开记证据；某平台缺失是未验证，不代表已覆盖 |
| 各供应商独立联调 | QQ、163、126、个人 Gmail、Workspace、飞书、标准工作邮箱 | 专用测试账号；管理员/用户资格明确；先只读，写入另有明确账号/收件人/范围授权 |
| P2 / 可选预览环境 | Outlook/365、iCloud、企业邮箱、Agently、官方 Gmail MCP | 只有实现已进入待测包且有资格时才可运行；首期不把缺项当已支持 |

不能把全部用例和全部环境直接做笛卡尔积。每个未来轮次只冻结对该环境适用且用户明确选择的集合，并递归加必要依赖；CLI-only 产品不要求一个不存在的 MCP 实现。供应商联调、模拟异常和平台权限分开准备范围。缺测试账号、预览资格或故障注入能力，是所选测试缺前置条件，不是已经通过或产品不适用。

只用合成账号 A/B/C 与 `.invalid` 地址描述夹具，不向这些虚构地址发真实邮件。真实联调的账号和收件人由本机私有配置解析，设计稿不填值。准备边界日期、三页互异邮件、重复 Message-ID、线程头、人工摘要答案、普通/链接/损坏/扫描附件、同名哨兵与已知字节哈希。异常实验只用隔离服务，不能对个人邮箱实施故障或破坏性探测。

证据必须可独立验证：发送既核对原生接受记录又核对接收/服务端计数；草稿与管理读回实际邮箱状态；附件对已知哈希；拒绝场景比较受保护目录内容/模式/副本集合，并用已启动的观测正控制证明日志有效。只看到命令退出 0、模型说成功或空日志都不足以通过。

## 5. 依赖与结果分支

依赖采用 `dependsOn`，只在目标需要上游当前证据或准备状态时使用。同一轮同一环境的当前有效通过才满足依赖；跨环境、上一轮通过、partial/skipped、未解决失败或过期证据都不满足。上游重测后，下游旧通过需要重新核验，不能把旧证据刷新成新通过。

基础依赖是 EM-BASE-001 → EM-BASE-002。典型必要链为 LOCAL-001 → LOCAL-002、LOCAL-001 → AUTH-001 → READ-001、DRAFT-001 → DRAFT-002/003、SEND-001 → SEND-002、SEND-008 → SEND-009。供应商资格拒绝、认证错误、非法路径等测试只依赖隔离准备，不要求先有正常登录，否则会错误阻止负向测试。

所有用例都有 passed/failed/partial/blocked/skipped 五个分支。passed 可建议一个具体后续目标或 done；failed 建议保留失败后显式复测同一用例；partial 补齐未核验断言；blocked 等待该用例列明的前置条件恢复；skipped 仅记录明确的范围排除。建议重试不等于自动再次发送或改变环境。

`done` 只表示此用例的分支无后续建议，不关闭整个测试轮，不清除其他失败。路由目标在冻结集合外时仅提示 out-of-scope，不能追加执行。设计 JSON 没有 `when`、跨用例谓词或编造的状态枚举。

## 6. 结果记录与验收口径

正式执行才创建受控轮次和观察记录：轮次 draft → ready → running → completed；执行 untested → running → passed/failed/partial/blocked/skipped。`untested` 是未执行阶段，不向用例定义伪造 pending 状态；本次没有生成任何观察。

- 全部必需断言经有效证据满足才能 passed；一个已确认违约即 failed，不能以“部分完成”掩盖。
- 仅有部分断言未验证时用 partial，并写明完成/未完成项。确切前置缺失时可 blocked；测试前 defer 的执行时间为 null，不伪造开始事件。
- 重测追加新尝试、事件和观察，保留旧失败。另一账号、另一用例或 skipped 不能清除原失败。
- 轮次 completed 只是记录收敛，不是全部通过；结论与精确 archive revision、来源、环境和证据绑定。本次没有 conclusions 文件或发布批准。
- 性能验收的时延、吞吐和长期稳定时长没有在当前需求中定量定义，本次不编造阈值。查询预算与重试次数按已有技术约定核验；若后续要性能 SLO，需要补需求、方法、基线和独立用例。
- CLI/MCP 确认不能代替真人许可，模拟服务不能代替真实邮件联调。没有选定实现包时，产品用例仍待测；结构校验通过不是邮箱功能通过。
