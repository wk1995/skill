# 初版实施与验证记录

本轮从 `b81b7eba67c76951688a7f845345fe550e72ca58` 开始。实现目标为一个可移植 `email-management` Skill、按需读取的供应商说明，以及仓库外的本机账号索引工具；不实现新的邮件协议客户端、不操作真实邮箱。

版本评估：新组件 `metadata.version` 初始为 `0.1.0`，同步组固定为 `email-management`。这是首次实验性开发基线，无旧版兼容迁移；修改 Agent 构建内容不改变现有 adapter 版本，不宣称已经发布或安装。`[Unreleased]` 保留开发说明，初始条目记录目录验证所需的版本声明。

## 实施边界与不变量

- portable core 只包含通用任务路由、操作语义和信息边界；工具命令、依赖和本机目录细节放参考文档。
- 新增 helper 只管理非秘密账号信息及原生配置引用；不接收凭据、不启动邮件工具、不把登记的地址当作后端已验证身份。
- 本机索引、锁、备份及临时文件只能写入仓库和 Skill 源码/安装目录之外；直接调用 `put` 和 `remove` 也要先校验再首次写入。
- 显式配置损坏或缺失时不切换默认账号；未知字段、秘密字段、冲突地址、错配后端和不安全原生配置引用均拒绝。
- 写入采用私有文件、互斥锁、同目录原子替换和上一份有效备份。拒绝及失败不改变其他账号；重复登记相同配置不重复写入。
- 初版自动化文件权限验证仅在 POSIX 提供；其他系统的变更入口明确拒绝，不能把不存在的 Windows ACL 验证宣称已实现。
- 供应商说明使用真实工具契约，执行前读取已安装版本的帮助/schema；所有写入仍需正确身份、范围及真实授权。缺少可验证冻结载荷能力时不能自动发送可变文件或草稿。
- 已先完成 Skill 核心，再将四份设计文件和本记录一起迁入所属 `doc/`；修复当前导航，不改写指向历史提交的需求基线证据。私人配置与测试运行证据不迁入仓库。

## 待验证及限制

真实 QQ、网易、Gmail、飞书和工作邮箱均未联调；发送、附件处理和各后端的身份/权限/内容绑定仍须按参考文档在实际安装版本验证。缺少可靠载荷绑定时自动发送不可用，账号 helper 不能替代邮件协议客户端或任意附件文件写入器。

当前自动化运行环境为 macOS/POSIX。Windows ACL 没有实现，非 POSIX 入口拒绝执行；Linux 原生文件系统尚未在本轮运行。权限和目录描述符检查不构成抵御同 UID 恶意进程移动父目录的 OS 沙箱。未运行真实邮箱验收、后台任务、跨账户事务、并发压力或断电恢复测试，也未把 31 项本地回归映射成 94 条业务用例全部通过。

## 后续开发兼容修正：原生 profile 选择符

原生 CLI 的合法 profile 名称可能包含下划线，账号索引原先复用本地账号 ID 的限制，导致无法原样登记这类选择符。`profile()` 现在对 `instance` 单独允许下划线，本地账号 `id` 仍保持原限制；读回、直接 `put` 和 CLI 共用校验。已有合法引用及 schema 不变，无需迁移。这是未发布的 `0.1.0` 开发基线中的兼容输入扩展，保留于 `[Unreleased]`，不另行确定发布版本。

新增合成回归覆盖 CLI 登记、重读、重复登记，以及账号 ID/路径穿越/空格/大写/超长输入的拒绝和原文件保留，本地回归为 32 项通过。原有 31 项记录对应初版检查，不改写成业务验收；任何真实账号、原生 profile、授权状态和接入结果只记仓库外本机，不写入本节。最终提交仍需通过干净树门禁和相应构建检查。
