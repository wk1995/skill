# 源码版本列车

语言：[English](README.md) | **中文**

`source-version-train` 约束任意仓库的需求从功能分支、版本集成和发布，到形成已评审源码提交及不可变 Tag 的完整代码链路。它不构建、签名、打包或上传发布产物。

## 如何使用

请尽可能提供仓库、需求或分支名称、版本号和目标代码阶段：

```text
使用 source-version-train 为这个需求创建功能分支。
将 feature/login 和 feature/report 选入 dev/1.4.0。
列出已经满足代码集成条件的需求 PR。
将通过评审的代码提升到 publish/1.4.0，并完成源码 Tag。
```

该 Skill 会解析默认分支，在版本确定前保留独立需求分支，检查 PR 就绪状态，提升已评审代码，并更新仓库内的版本元数据。发布分支默认是受保护的 `publish/<version>`，也可以通过发布分支模板指定其他名称，例如 `release/<version>`；修改只能经评审的 PR 进入，不能直接推送。检查通过后，它先把该分支 rebase 到默认分支并推送，再重新检查。仓库有 CI 打包时，通过 `build-pipeline-engineering` 打包这个提交；没有 CI 打包时，检查通过即可。随后调用发布接口，默认实现包括 FIR、GitHub Actions Artifacts 和 `wk1998.io`，一个实现成功即通过。只有这时才给该提交打 Tag，并合并回默认分支。完整约束见 [SKILL.md](SKILL.md)。

新建版本集成分支时，按仓库自身的版本规则初始化全部版本值；已有分支经过校验后复用，不重复递增。有项目流程脚本时使用统一入口，没有脚本时通过 Git 和版本文件操作完成同样的初始化。不要求特定脚本、版本编码公式、语言或分支命名。发布保留已初始化的目标版本；提前创建的发布分支从记录的默认分支基准提交创建。

## 何时触发

适用于需求分支、版本范围选择、`dev/<version>` 集成、受保护的发布分支、代码门禁、源码版本元数据、把已验证的发布 rebase 到默认分支，或源码 Tag。

## 何时不触发

不要用于配置或执行签名、打包、校验和生成、构建输出保留、产物上传、应用商店交付或包发布；这些请求使用 `build-pipeline-engineering`。普通代码修改如果不涉及版本列车，也不触发本 Skill。
