# 数据库工程

语言： [English](README.md) | **中文**

`database-engineering` 用于 PostgreSQL 和 MySQL 数据库的设计、审查、优化、迁移与排障，结合工作负载证据、版本差异、变更验证和恢复计划开展工作。

## 如何使用

说明工程任务，并提供数据库类型与版本、表结构或迁移文件、已有的 SQL 和执行计划，以及期望的是审查、文件修改还是实际执行。Skill 会优先读取项目已有信息；没有数据库凭据也可以准备离线方案。

示例请求：

```text
审查这份 PostgreSQL 17 订单表设计，检查约束、索引和租户隔离。
结合 EXPLAIN 输出和已有索引，诊断这条 MySQL 8.4 慢查询。
重写应用中的 PostgreSQL 查询，保持 NULL 处理和分页结果不变。
为这张 MySQL 大表准备扩展、回填、收缩迁移，只修改文件。
根据连接池指标和等待事件，排查 PostgreSQL 连接耗尽。
为 PostgreSQL 备份制定恢复演练方案和验证步骤。
```

输出包括具体发现、SQL 或文件变更、证据、验证步骤，以及适用的上线和恢复方案。实际执行遵循已经授权的目标与范围；准备迁移文件不会直接执行迁移。没有运行时测量时，不会把性能改善描述为已验证。

Skill 沿用已有服务商、ORM 和迁移工具，提供操作指导并使用工作环境中可用的工具，不自带数据库客户端，也不自动开通数据库。参考文档以 PostgreSQL 17 和 MySQL 8.4 为基准，不代表对其他版本的兼容承诺。

## 何时触发

- PostgreSQL/MySQL 的表结构、约束、索引、应用 SQL 或迁移工作。
- 慢查询和执行计划分析，锁竞争、死锁、连接耗尽与复制延迟排查。
- 维护、备份验证、恢复方案制定或已授权的实际执行。
- PostgreSQL 行级安全策略，或 ORM 生成的数据库变更审查。

## 何时不触发

- 仅查询业务数据、计算指标或制作报表，不涉及数据库工程任务。
- SQLite、SQL Server、Oracle、MongoDB、Redis、独立向量数据库等其他引擎的专属任务。pgvector 等 PostgreSQL 扩展仍属于 PostgreSQL 工作，但需要查阅扩展专属文档。
- 单纯选择数据库产品、服务商或 ORM，处理账单，或不涉及数据库工程的基础设施开通。
- 既不修改也不调查 SQL、表结构或数据库行为的应用代码变更。
