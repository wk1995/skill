# 版本升级约束

语言：**简体中文** | [English](README.md)

`version-upgrade-policy` 用于定义和评审自定义版本格式的升级方式。它明确每个部分的含义，但不假设版本一定是三个纯数字的 SemVer。

## 如何使用

提供当前版本、目标版本、变更内容以及项目已有的格式规则：

```text
使用 version-upgrade-policy 判断 2026.09.1 -> 2026.10.0 是否属于功能发布。
为 A.B.C 设计 CI 规则，其中 A 表示兼容性、B 表示能力、C 表示维护修复。
评审 1-rc-7 -> 1-rc-8 是否是合法的维护升级。
```

该 Skill 会记录版本语法、各部分含义、非数字后继规则、兼容性依据、changelog 要求和验证场景。具体操作见 [SKILL.md](SKILL.md)。

首次发布时，可以指定初始值，或采用项目已有规则要求的值；两者都没有时，默认使用数字版本 `0.0.1`。若明确选择的自定义格式无法表示 `0.0.1`，Skill 会询问符合该格式的初始值。已有发布不会重置为默认值，仅缺少版本文件也不代表组件是新建的。

## 何时触发

版本规则、发布升级判断、自定义版本格式、changelog 发布依据，或校验这些规则的 CI 检查，应使用此 Skill。

## 何时不触发

仅做依赖版本解析、包选择，或已有明确规则下的检查器实现，且无需判断版本策略时，不使用此 Skill。
