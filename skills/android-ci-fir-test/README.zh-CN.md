# Android CI FIR Test

语言：[English](README.md) | **简体中文**

`android-ci-fir-test` 串联 Android FIR 渠道 CI 打包、基于 PR 的回归用例，以及按需执行的真机测试和可复用测试轮次。普通 CI 只归档产物，上传 FIR 必须明确要求发布。Skill 初始版本为 `0.0.1`。

## 如何使用

提供仓库、源码引用和关联 PR（如果已知），按需指定阶段：

```text
用 CI 打一个 dev_5.1.3 分支的 FIR 渠道 Release 测试包，并给我 PR #44 的回归用例。
把 CI run <run-id> 已验证的包发布到 FIR。
把刚才的 CI APK 安装到已连接的测试手机，并执行已准备的短时用例。
准备下一轮测试：上轮失败优先，每轮包含全部冒烟，再加入发布 PR diff 得出的用例。
```

第一条只打包并归档，不发布；第二条明确授权 FIR 发布。安装和测试仅在要求时执行。构建类型默认 Release，用户指定的变体优先。复用现有测试工作台，每次观察记录已登记设备和执行时间，并保留历史。

详细流程见 [SKILL.md](SKILL.md)，源码与产物核验见 [CI 与发布](references/ci-and-publication.md)，用例、设备和结果处理见 [测试轮次](references/test-rounds.md)。示例分支名和 PR 编号不是默认值。

## 何时触发

- 从指定源码引用，通过 CI 打包 Android FIR 渠道测试 APK。
- 为该包根据 PR 生成回归用例，以及明确要求的可选 FIR 发布。
- 同一测试包流程中的后续安装、设备测试或重复测试轮次。

## 何时不触发

- 不使用 CI 的本地 Gradle 打包或本地 FIR 上传。
- 与此 FIR 测试流程无关的通用 CI、Google Play、SDK、AAR 或插件打包。
- 独立测试工作台开发，或无关的 QA 规划。
- 未单独要求的源码版本修改、分支晋级、代码修复、PR 创建、合并或打标签。

仅要求 CI 测试包或用例清单，不会自动开发网页、安装应用或修复缺陷。
