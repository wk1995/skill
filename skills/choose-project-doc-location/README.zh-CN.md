# 选择项目文档位置

语言：[English](README.md) | **中文**

`choose-project-doc-location` 为项目文档选择路径，并整理指定文件夹或项目下的文档位置。适用于 PRD、技术文档和机器可读状态机规格文件，不管理它们的业务关联或内容 Schema。

## 如何使用

提供文档类型、所属项目、已知的现有路径以及明确指定的目标位置。需要整理时，指出要处理的文件夹或项目。该 Skill 判断归属，给出路径和简短理由；收到整理请求时，先列出原路径到目标路径的映射，再执行归属明确、无冲突的迁移。

```text
Android 配对需求的 PRD 和技术方案应该放在哪里？
更新 sync-skills Skill 已有的 PRD。
整理 skills/example-skill/ 下的文档位置。
整理当前项目 notes/ 文件夹里的文档。
整理整个 Skill 仓库下的文档位置。
只检查 notes/ 中的文档并建议位置，不移动文件。
```

用户明确指定的位置优先。更新内容默认使用已有位置，并提示位置不符合约定的文档。新建文档和明确要求的整理采用下列规则，同时保留仓库要求的文件位置。仅咨询建议时不移动文件。

## 默认位置

统一应用可以包含多个代码模块，这不意味着每个模块都是独立项目。独立维护的项目（例如本仓库各个 Skill）拥有各自的文档。该 Skill 结合项目说明、入口、构建或发布边界判断归属。

| 文档范围 | 默认位置 |
| --- | --- |
| 统一应用的需求文档，例如 Android 功能需求 | `<项目根目录>/doc/<需求目录>/` |
| 单个独立项目或 Skill | `<所属项目>/doc/`，例如 `skills/<skill-name>/doc/` |
| 独立项目中的多个需求 | `<所属项目>/doc/<需求目录>/` |
| 多个独立项目共同的需求文档 | `<仓库根目录>/doc/<需求目录>/` |
| 项目介绍、快速上手和导航 | 所属项目的 `README.md` 及其语言版本 |

PRD、技术文档和状态机规格文件使用同一套归属规则。目录使用单数 `doc`，复用匹配的已有需求目录，不规定文件格式和名称。仓库公共指南可以保留在已有 `docs/`；Wiki 适合与代码版本关联较弱的知识。

## 整理已有文档

指定文件夹时，递归处理其中的候选文档；指定项目时，处理该项目。文件可以从指定文件夹移动到所属项目的 `doc/`，但不会越过项目边界，除非用户明确指定了更大的仓库范围。迁移时可以同步修复所属项目其他位置中的路径引用。

该 Skill 先展示原路径、目标路径和理由，再迁移归属明确的文件。保留文件内容及 Skill 入口、README、CHANGELOG 等必须留在原位的文件。修复移动影响的链接和资源路径，并检查已完成文件再次整理时应保持原位。

归属不清、目标冲突和超出范围的迁移会保留原文件并说明原因，其余明确的迁移可以继续。不会把生成文件、依赖、运行时数据或指向范围外的符号链接目标当作待整理文档。结果列出已移动、保持原位及尚未解决的文件。本地整理不会向 Wiki 发布内容。

完整的位置选择和迁移流程见 [SKILL.md](SKILL.md)。

## 何时触发

在创建或更新项目文档前选择路径、检查已有文档位置，或整理指定文件夹或项目下的文档时使用。适用于 PRD、技术文档、机器可读状态机规格文件、README、仓库指南和 Wiki 位置请求。直接点名 README 或 Wiki 时仍可检查位置，同时遵循用户明确指定的目标。

## 何时不触发

应用代码、运行时快照或缓存、非文档资源，以及 Agent Skill 副本管理和同步不适用。没有路径任务时，定义需求 ID、文档关联、状态机 Schema 或业务语义不属于本 Skill 的职责。JSON/YAML 状态机规格文件可以作为待整理文档，但本 Skill 只决定其路径。迁移时修复失效路径引用不会引入业务追踪关系。
