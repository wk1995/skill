# 选择项目文档位置

语言：[English](README.md) | **中文**

`choose-project-doc-location` 根据内容和所属项目，为项目文档选择存放位置，包括 PRD、技术文档和机器可读的状态机规格文件。

## 如何使用

说明需要记录的信息、所属项目或需求，以及期望的存放位置。该 Skill 会先检查项目结构和已有的文档约定，再指导后续的文档修改。即使请求写了“README”或“Wiki”，也会触发位置检查；对于用户明确指定的位置，会遵循该要求并说明相关取舍。

例如：

```text
为新贡献者记录部署流程。
这段项目概览应该写进 README 还是 Wiki？
整理新集成相关的仓库文档。
为 Android 设备配对需求编写 PRD、技术方案和机器可读的状态机规格文件。
更新 sync-skills Skill 的 PRD 和状态机规格文件。
```

## 需求文件放在哪里

同一需求的 PRD、技术文档和机器可读状态机规格文件应放在一起：

| 项目结构 | 存放位置 |
| --- | --- |
| 代码入口统一的项目，例如 Android 应用 | `<项目根目录>/doc/<需求目录>/` |
| 仓库内包含独立项目，例如本仓库的各个 Skill | `<所属项目>/doc/`；Skill 对应 `skills/<skill-name>/doc/` |

目录名使用单数 `doc`。独立项目需要区分多个需求时，可以在自己的 `doc/` 下再建需求子目录。例如，Android 配对需求可以在 `doc/device-pairing/` 下放置 `prd.md`、`technical-design.md` 和 `state-machine.yaml`；Skill 可以在 `skills/sync-skills/doc/` 下放置 `prd.md`、`technical-design.md` 和 `state-machine.json`。文件名和格式仅为示例，只创建用户需要的文件。

已有的仓库公共说明可以继续放在根级 `docs/`。README 保留概览和链接；Wiki 适合与代码版本关联较弱的知识。更新前先查找已有文件：若任务包含整理或迁移，则迁移时同步更新引用；否则原地更新并说明位置不一致，避免创建重复副本。

完整的位置选择规则和编辑指南见 [SKILL.md](SKILL.md)。

## 何时触发

当需要创建、更新、改写或整理项目文档时使用，包括 PRD、技术文档、机器可读状态机规格文件、README 内容、仓库文档、项目说明、工作流文档、架构说明、上手指南或 Wiki 材料。用户直接点名 README 或 Wiki 时也会触发，因为仍需根据内容与仓库约定检查位置。

## 何时不触发

普通代码修改、运行时状态快照或缓存、非文档资源变更，以及管理或同步 Agent Skill 副本时，不使用此 Skill。作为项目文档的 JSON/YAML 状态机规格文件属于适用范围；在应用代码中实现状态机不属于此范围。
